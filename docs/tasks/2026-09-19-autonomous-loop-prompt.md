# 自动推进编排提示词（长跑模式）

> 使用方式：当你希望**一个会话持续多轮自动推进**评审与修复，而不是人工一轮轮催，把本文件交给执行会话。
> 如果你只需要跑一轮评审或一轮修复，请直接用同目录的 `2026-09-19-three-perspective-review-prompt.md` 与 `2026-09-19-remediation-prompt.md`；本文件是它们的编排外壳。

---

## 目标（不可变）

完成 `E:\ai_project\insurance_recommendation` 的产品 / 设计 / 开发三视角评审与修复，直到：

- 所有 P0 项闭环；
- 所有 P1 项闭环或降级为有记录的遗留项；
- `pytest` / `npm run build` / `playwright` 全量通过；
- 报告中不存在未验证的结论。

---

## 执行节奏

**每轮只做一件事，做完立刻落盘，不要一次做完。** 磁盘上的文档是唯一的跨轮记忆。

### 轮次 1：评审（只读）

按 `2026-09-19-three-perspective-review-prompt.md` 执行三视角评审，产出 `docs/tasks/2026-09-19-three-perspective-review.md`。
本轮**不得修改任何既有代码 / 配置 / 文档**（唯一允许的写入是这份报告）。

### 轮次 2：拆卡

读评审报告，把 P0 / P1 项拆成任务卡写入 `docs/tasks/2026-09-19-remediation-cards.md`（含证据、验收标准、验证命令、批次、依赖）。
同时把需要人类拍板的产品决策问题抽取到 `docs/tasks/2026-09-19-open-questions.md`。

### 轮次 3+：逐卡修复

每轮取**一张**未完成任务卡（按批次与依赖顺序），执行：

1. 复现 → 修复 → 新增回归测试 → 跑全量三命令 → commit → 更新任务卡状态与 handoff。

### 收尾轮

全量三命令最后一次跑，产出 `docs/tasks/2026-09-19-remediation-handoff.md`，输出最终交付说明。

---

## 硬性约束

1. **每轮开始先读磁盘**：读 `docs/tasks/` 下最新的卡片与 handoff，确认上一轮结论与当前代码一致。**代码是唯一事实**，文档可能过期。
2. **任何"已验证"必须附真实命令输出**；无法验证就写"未验证"。
3. **一轮只改一个主题**：避免大杂烩 commit 导致无法回滚。
4. **不自己拍板产品决策**：遇到"是否去掉某字段 / 套餐命名是否改 / 免责声明措辞"这类问题，记录到 `docs/tasks/2026-09-19-open-questions.md` 并继续做其他任务。
5. **不得削弱测试**：禁止为凑绿删除测试、跳过用例、放宽断言。正确行为与既有测试冲突时，更新断言语义并说明理由。
6. **不得越界**：不引入新依赖 / 新中间件 / 范围外重构；模型字段变更必须配 Alembic 迁移。
7. **每轮结束必须全绿**：任一命令为红则下一轮先修红，不得继续推进新任务。

---

## 每轮必须输出的内容

- 本轮做了什么（一句话）；
- 复现命令与真实输出摘要；
- 变更文件清单；
- 测试结果（三命令的真实结论）；
- commit hash 与 message；
- 更新了哪些文档、下一轮计划；
- 当前未闭环项与原因。

---

## 停止条件

满足以下任一条件时停止并汇报：

- 第 6 节"目标"全部达成；
- 遇到连续 3 轮无法推进的同一阻塞（如环境缺失、需要人类决策且已无其他可做任务）——此时明确说明阻塞条件，而不是继续空转。
