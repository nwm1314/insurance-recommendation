# v0.1.0 — first public release

This is the first tagged release of Insurance Recommendation, an open-source decision-support
tool for personal insurance planning. The repository had no tags or releases before this
version, so the notes describe the initial state of the codebase rather than a diff against a
previous release.

The project is MIT-licensed and independent: it is not affiliated with any insurer, broker or
comparison site, and it does not sell insurance.

## Highlights

- **Rules decide, AI explains.** Eligibility (age, occupation class, product status, age/type
  policy matrix, per-type budget admission) is enforced in SQL/Python before any model runs.
  The optional LLM layer can only re-rank products that already survived the rules, and its
  selection is re-checked against the budget.
- **Auditable ranking.** Eight scoring dimensions with type-specific weights stored in
  versioned YAML; premium competitiveness is a within-type rank percentile, and undisclosed
  premiums get a neutral score instead of a fake one.
- **Three budget-aware portfolios.** Packages at 0.5/0.8/1.0 budget multipliers, layered into
  basic/core/supplementary, with one substitution for a missing required type and per-type
  coverage gaps in CNY. Names describe the trade-off rather than implying that a higher premium
  is better.
- **Deterministic fallback.** Missing key, provider error, timeout, invalid response or an
  exhausted daily quota all return a complete rule-based answer (`engine_mode: "degraded"`),
  never a broken page.
- **Product data with provenance.** Aggregator-first crawling with `robots.txt` and SSRF
  checks, LLM extraction validated against a schema whitelist, confidence-gated auto-publish
  with audit, a human review queue, a version chain with rollback, and freshness labelling.
- **Privacy defaults that are explicit.** Saved recommendation records are Fernet-encrypted
  when a key is configured; without one the app logs a warning (an error in production) rather
  than pretending the data is protected.

## What is in the box

- FastAPI backend: recommendation, catalog and comparison, auth with permission-based RBAC,
  self-service profiles and history, admin and ingestion APIs.
- React 18 + TypeScript + Ant Design frontend: questionnaire, result and comparison views,
  account page, admin console; responsive down to 320 px.
- Ingestion pipeline: discovery, fetch, extraction, validation, review, publish, verification,
  off-shelf detection, scheduled maintenance.
- Docker Compose stack: PostgreSQL 16, Redis 7, backend, Nginx frontend; Alembic migrations with
  a fail-closed startup schema gate.
- English documentation (`README.en.md`, `docs/en/*`) alongside the existing Chinese docs.
- Community files: contributing guide, security policy with private reporting enabled,
  Contributor Covenant 2.1, issue forms and a PR template.

checkout.

## Upgrade notes

- **First release.** There is no upgrade path from pre-release snapshots. Deploy from the tag,
  not from an older working copy.
- **Version strings.** Project version is `0.1.0` (`backend/main.py`, `frontend/package.json`,
  lockfile). `ENGINE_VERSION` (1.1.0), `RULE_VERSION` (2) and the scoring-weights version (2)
  are engine-level identifiers used to reproduce stored results and are intentionally
  independent.
- **Required configuration for Compose.** `LLM_API_KEY`, `JWT_SECRET_KEY`, `POSTGRES_PASSWORD`
  and `DATABASE_URL` are hard requirements; Compose refuses to start without them.
- **Required for any real users.** Set `RECORD_ENCRYPTION_KEY` before the first real user.
  Changing it later makes existing encrypted records unreadable.
- **Production pool.** `SEED_DEMO_PRODUCTS=false` is the production default, so a fresh
  deployment starts with an empty product pool until ingestion publishes reviewed products.
  That is expected behaviour, not a defect.
- **No deployment side effects.** The repository contains test workflows only. Publishing this
  release does not deploy or restart anything.

## Known limitations

- Premiums are the lower bound of a quoted range; there is no binding quote, no real-time
  underwriting and no purchase or lead-capture flow.
- No regional (province/city) eligibility dimension, because product data does not carry it.
- Chinese mainland catalog and Chinese-language UI; no i18n layer.
- AI mode depends on an external OpenAI-compatible endpoint; latency, quota and availability
  apply, and it degrades to rule mode.
- The demo catalog is for local and E2E use; it is not verified product data.
- `RECORD_RETENTION_DAYS` is reserved; no retention job runs in this version.
- Backend must run as a single replica unless non-primary replicas set
  `SCHEDULER_DISABLED=true`.
- No linter or formatter is configured.
