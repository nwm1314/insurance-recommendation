# v0.2.0 — retention, a bilingual interface, and the CI gaps closed

`v0.2.0` is a minor release: three improvements that were listed as the highest-value follow-ups
after `v0.1.0`, plus the release-process plumbing that keeps them honest. No database migration,
no API shape change, no new required configuration.

## Highlights

- **The interface now speaks English.** A zh-CN / en-US dictionary drives the whole user-facing
  UI, with a header toggle, `?lang=en` deep links and a persisted preference. Product, insurer
  and condition names stay Chinese on purpose — they are the terms users will check against the
  insurer's own documents.
- **`RECORD_RETENTION_DAYS` is actually enforced.** Previously the setting existed and the docs
  described a retention window, but nothing deleted anything. A positive value now registers a
  daily job that removes recommendation records past the window; `0` keeps the old behaviour.
- **The catalog has a written data policy.** Sources and their roles, what is and is not
  collected, how snapshots are used, attribution and freshness, and a correction/takedown route
  that goes through a dedicated issue form.
- **CI covers what it previously ignored.** Frontend build, documentation links, and container
  builds now fail loudly instead of surfacing after a release.

## Added

### Recommendation record retention

- Daily APScheduler job when `RECORD_RETENTION_DAYS > 0`. It hard-deletes rows in
  `recommendation_records` whose `created_at` is strictly older than the cutoff; user-saved
  profiles are never touched.
- `backend/scripts/purge_expired_records.py` — the manual equivalent for deployments running with
  `SCHEDULER_DISABLED=true`, with `--days N` and `--dry-run`.
- Six tests: the `0` no-op path, dry-run, window boundaries, job registration with and without a
  configured window, and the saved-profile boundary.

### Bilingual interface

- `frontend/src/i18n/` — a flat `key: text` dictionary for `zh-CN` and `en-US`. `MessageKey` is
  derived from the Chinese map, so a missing English entry is a type error.
- Language resolution: `?lang=` → `localStorage` → browser language (English only) → Chinese. The
  header toggle persists the choice; Ant Design's own locale follows.
- App shell, questionnaire, result page, sign-in/registration, account page and shared components
  all render from the dictionary.
- Two Playwright cases cover `?lang=en`, switching back to Chinese, and the English sign-in page.

### Data policy and takedown route

- `docs/data-policy.md` and `docs/en/data-policy.md`: source platforms and their roles (including
  the aggregator that had to be retired because its `robots.txt` disallows crawling), collection
  scope, raw snapshots and why no API serves them, attribution and freshness, accuracy limits,
  correction/removal, operator responsibilities, and the license boundary between code and
  third-party content.
- A "Data correction or takedown" issue form and a `data` label.

### CI

- `Frontend Build`: `npm ci` plus `npm run build` (type check + production build).
- `Docs`: relative-link check (standard-library script) and issue-template YAML validation.
- `Docker Build`: builds both images and validates `docker compose config`, on Docker-related
  paths and manual dispatch. It pushes and deploys nothing.

## Changed

- `COMPANY_URLS` moved from `backend/scripts/seed.py` to `backend/app/catalog_sources.py`;
  `seed.py` re-exports it. The recommendation API no longer imports a CLI script (the REC-005
  layering inversion), guarded by tests.
- CI uses Python 3.12 (matching the backend image) and Node 22; the workflow actions moved off the
  deprecated Node 20 runtime; every workflow gained a concurrency group.
- README (both languages), the architecture/development/deployment guides and the Chinese
  deployment runbook document retention, the language switch and the data policy.
- Staging deployment references now point at `master`; `v0.3.0` and `develop` references that no
  longer matched the repository are gone.

## Breaking changes

None for the API, the database or the deployment contract.

Two behaviour notes, because they are visible:

- With no stored preference, an English browser now gets an English interface. A Chinese browser
  still gets Chinese, and the toggle overrides either way.
- The application version string reported by `/` and in the OpenAPI document is `0.2.0`.

## Upgrade notes

- **No migration.** The Alembic head is unchanged (`20260914_0002`); `alembic upgrade head` is a
  no-op on an existing database, and the startup schema gate still applies.
- **No new required variables.** `RECORD_RETENTION_DAYS` is optional and defaults to `0`
  (keep forever). Setting it is the only way to enable deletion, and deletion is irreversible —
  export first if you need an archive.
- **Compose is unchanged.** Rebuild the images to pick up the frontend and API version changes.
- Manual cleanup on replicas with `SCHEDULER_DISABLED=true`:
  `python backend/scripts/purge_expired_records.py --days 365 --dry-run` before running it for
  real.

## Known limitations

- Admin screens remain Chinese-only.
- Backend-generated text — recommendation reasons, rule summaries, AI narratives, validation
  details — stays Chinese regardless of the UI language; the interface language applies to static
  UI copy.
- The production bundle's main chunk is now 512 kB (168 kB gzip), which triggers Vite's 500 kB
  advisory. The dictionary is loaded statically; splitting the English half into a lazy chunk
  would remove the warning at the cost of a first-paint language switch.
- `RECORD_RETENTION_DAYS` deletes hard, with no archive and no soft-delete flag.
- Single-scheduler assumption is unchanged: one backend replica may run the scheduler.
